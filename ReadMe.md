# Nocker

**Nocker** — это легковесный аналог Docker, предназначенный для работы на системах с ограниченными возможностями (например, старые ядра Linux, Android, роутеры на ARM и пр.), где недоступны cgroups, user namespaces и подобные современные технологии изоляции. Вместо этого Nocker использует `chroot`/`proot` для создания контейнеров. Проект написан на чистом POSIX Shell для максимальной портативности и минимальных зависимостей.

> **Важно:**  
> Nocker не претендует на полную функциональность Docker. Это proof-of-concept, который реализует базовые возможности управления контейнерами, но многие продвинутые функции либо отсутствуют, либо находятся в разработке.

## Возможности

На данный момент реализованы следующие команды и функции:

- **Образы:**
  - `nocker pull IMAGE`  
    Загрузка образа.

- **Контейнеры:**
  - `nocker run [options] IMAGE [COMMAND]`  
    Создание и запуск нового контейнера. Поддерживаются опции: `--detach, --rm, --restart <policy>, -v/--volume, -p/--publish, -e|--env, --env-file, -w/--workdir`
  - `nocker start [options] <container_id_prefix>`  
    Запуск ранее остановленного контейнера.
  - `nocker exec [options] <container_id_prefix> COMMAND [ARGS...]`  
    Выполнение команды внутри запущенного контейнера.
  - `nocker stop <container_id_prefix>`  
    Корректная остановка контейнера.
  - `nocker restart <container_id_prefix>`  
    Перезапуск контейнера (реализовано как последовательный вызов `stop` и `start`).
  - `nocker kill [--signal=SIGNAL] <container_id_prefix>`  
    Отправка указанного сигнала процессу контейнера.
  - `nocker logs [options] <container_id_prefix>`  
    Вывод логов контейнера с поддержкой флага `-f` (follow) и опцией `--tail`.  
    **Примечание:** Некоторые опции (`--since`, `--until`, `--details`) не поддерживаются.
  - `nocker inspect <container_id_prefix>`  
    Вывод метаданных контейнера в формате JSON.
  - `nocker ps [options]`  
    Список запущенных/остановленных контейнеров. Поддерживаются опции для фильтрации, вывода только идентификаторов `-q` и отображения размеров `-s`.
  - `nocker rm [options] <container_id_prefix> [<container_id_prefix> ...]`  
    Удаление одного или нескольких контейнеров. Поддерживается опция `--force` (или `-f`).
  - `nocker prune [--force]`  
    Удаление всех остановленных контейнеров. Опция `--filter` пока не реализована.

- **Альтернативный синтаксис команд для контейнеров и образов:**
  - `nocker container <subcommand> ...`  
    (например, `nocker container run`, `nocker container ps`, `nocker container rm` и т.д.)
  - `nocker image pull ...`

## Примеры использования

Ниже приведены примеры команд, схожих по синтаксису с Docker:

### Работа с образами

- **Загрузка образа:**
  ```sh
  nocker pull alpine
  ```

- **Альтернативный вариант:**
  ```sh
  nocker image pull ubuntu:20.04
  ```

### Работа с контейнерами

- **Запуск контейнера в интерактивном режиме:**
  ```sh
  nocker run -it alpine:latest /bin/sh
  ```

- **Запуск контейнера в фоне (detach):**
  ```sh
  nocker run -d alpine sleep 100
  ```

- **Вывод списка контейнеров:**
  Работающих:
  ```sh
  nocker ps
  ```
  или
  ```sh
  nocker container ls
  ```
  Всех:
  ```sh
  nocker ps -a
  ```

- **Остановка контейнера:**
  ```sh
  nocker stop <container_id_prefix>
  ```

- **Перезапуск контейнера:**
  ```sh
  nocker restart <container_id_prefix>
  ```

- **Удаление контейнера:**
  ```sh
  nocker rm <container_id_prefix>
  ```

- **Выполнение команды внутри контейнера:**
  ```sh
  nocker exec -it <container_id_prefix> /bin/sh
  ```

- **Просмотр логов контейнера:**
  ```sh
  nocker logs -f <container_id_prefix>
  ```

- **Инспекция контейнера (просмотр подробной информации):**
  ```sh
  nocker inspect <container_id_prefix>
  ```

## Что реализовано и что отсутствует

### Реализовано:
- **Базовые команды управления контейнерами и образами:** `pull`, `run`, `start`, `exec`, `stop`, `restart`, `kill`, `logs`, `inspect`, `ps`, `rm`.
- **Поддержка альтернативных синтаксисов:** `nocker container ...` и `nocker image ...`.
- **Обработка ряда опций в командах:** интерактивный режим, detach, публикация портов (частично), монтирование томов, установка переменных окружения, выбор рабочей директории.
- **Удаление остановленных контейнеров через `prune` с подтверждением.**
- **OverlayFS в chroot / аналог драйвера vfs в proot**

### Что пока отсутствует или реализовано частично:
- **nocker build:** Планируется реализовать в первую очередь.
- **nocker compose:** Планируется реализовать после nocker build.
- **Расширенные возможности фильтрации:** Например, опция `--filter` в команде `prune` выводит ошибку, что фильтры не реализованы.
- **Поддержка опций монтирования (`--mount`):** В данный момент рекомендуется использовать `-v` для томов.
- **Некоторые параметры логирования:** Опции `--since`, `--until`, `--details` (или `--timestamps`) не поддерживаются.
- **Автоматическое пробрасывание портов:** Опция `-P`/`--publish-all` только отмечена как TODO.
- **Изоляция и ограничения ресурсов:** Нет поддержки cgroups, user namespaces и подобных технологий, поэтому контейнеры изолируются лишь с помощью `chroot`/`proot`.

## Требования и установка

- **Операционная система:** Любая Linux-система с архитектурой CPU, для которой существуют контейнеры. Рекомендуется использовать на системах с минимальными возможностями ядра Linux (например, Android, роутеры на ARM и т.п.).
- **Хранение образов и контейнеров:**  
  - При запуске от имени `root` используется системный каталог `/var/lib/nocker`.
  - При запуске от обычного пользователя — используется каталог `$HOME/.local/share/nocker`.
- **Зависимости:**  
  - `proot`
  - `jq` для обработки JSON.
  - Стандартные Unix утилиты: `mkdir`, `mktemp`, `du`, `awk`, `grep`, `sed`, `bc`, `wget` или `curl`.

Для установки достаточно скопировать скрипты в выбранный каталог, добавив его в PATH и сделать nocker исполняемым. Или можно просто запускать `sh nocker ...`, находясь в директории скрипта.

## Заключение

**Nocker** — это экспериментальный инструмент для запуска контейнеров в условиях ограниченных системных ресурсов и возможностей ядра. Если вам требуется простая альтернатива Docker для старых или урезанных систем, Nocker может стать хорошим решением. Обратная связь и pull-реквесты с новыми фичами и исправлениями приветствуются!
